# 爬爬的随身听 0.3.0：双音乐库、专辑封面与歌词

状态：下一版本功能与架构方案，供用户确认。此次工作只制定计划，不实施产品改动或更新正在运行的主机。

## 1. 本轮确定的要求

用户要求以下功能全部进入下一版本，不能通过删减部分项目来宣称完成：

1. 显示专辑封面。
2. 显示专辑信息，并能以专辑组织曲库。
3. 显示歌词。
4. 修复此前“中文文件名保存失败”，恢复真实中文文件名读写。
5. 音乐库分成 SD 卡和云端 URL 两种来源。
6. 云端来源已由用户明确选择为自建 HTTP/HTTPS 曲库或 M3U 歌单，需要直接在线播放。

0.3.0 交付上述完整功能。下文开发阶段是实施顺序，全部通过后才作为完整下一版交付。

## 2. 现状与依据

- 0.2.0 是独立 C++/libnx NRO，具有 MP3 流式读取、重采样、音频缓冲、图形界面和触摸/手柄控制，已部署到 SD 卡。
- `Track` 目前只有路径、标题、歌手，标题/歌手从文件名拆分；尚无专辑、封面、歌词、源类型或稳定歌曲标识。
- 解码器只接本地 FILE 回调；在线数据源需要增加缓冲、取消、错误/EOF 区分及跳转机制。
- 中文 UI 显示与系统字体已存在，但此前通过 FTP 对中文文件名 STOR/RNTO 返回失败；同一音乐数据用 ASCII 名称成功，最终 5 首歌暂用拼音文件名。失败发生在哪一层仍未定位，不能据此认定 Switch/SD 卡不支持中文。
- 本地 `C:/Users/22969/Music/Music_JayZhou-master` 有 101 首 MP3、1 个 FLAC，没有独立 JPG/PNG/LRC/M3U 文件。抽查《稻香》《花海》《枫》有 ID3v1；《黑色幽默》有 ID3v2.3 的标题、歌手、专辑及 APIC 封面。不能把“没有开头 ID3v2”误判为“没有任何标签”。
- 0.2.0 软件测试通过不等于已完成主机音质、休眠和长时运行验证；下一版安排真机验收。

## 3. 推荐路线与取舍

保留现有 C++/libnx 播放器，统一歌曲资料和播放队列；SD 文件与 HTTP 数据源通过不同读取器接入同一播放引擎。延续奶油白、石墨绿、橙色的视觉与现有图标。

用户已选择 HTTP/HTTPS/M3U 作为云端来源。建议同时接收两种曲库入口：

| 入口 | 用途与取舍 |
|---|---|
| 结构化曲库清单 `library.json`，推荐用于自建库 | 明确提供歌名、歌手、专辑、音频、封面和歌词 URL；资料齐全、请求少，可以由桌面网页自动生成。 |
| M3U / M3U8 歌曲列表 | 兼容已有歌单；读取 EXTINF 和音频地址，补读音频标签及用户提供的资料。没有资料的条目明确标记缺失。 |

本范围采用原生播放器加标准化曲库入口这一条路线。网页目录列表的 HTML 样式不一致，也没有稳定的歌曲—封面—歌词关系，不把“抓取任意目录网页”当作曲库协议。无需重写 NRO 或引入 WebView。

M3U8 在此指 UTF-8 编码的歌曲列表；含 `#EXT-X-` 的 HLS 分段流不作为同一种格式误处理。本版主音频格式继续是 MP3，FLAC/WAV/OGG 属于另列的扩展建议，不削减已确定的任何需求。

## 4. 必做功能细节

### 4.1 歌曲资料与专辑

- 读取 ID3v2.3/v2.4；兼容已有文件的 ID3v1。标题、歌手、专辑、专辑歌手、音轨号、碟号、年份均可进入歌曲资料。
- 优先使用用户显式补充资料，其次有效标签，最后才回退到文件名。缺失字段使用“未知专辑”等明确文案，不编造内容。
- 支持规范中的 UTF-8、UTF-16 等文本编码；ID3v1 的历史中文编码按可配置兼容策略处理，不能简单当作 Latin-1 展示乱码。
- 本地与云端统一展示歌名、歌手、专辑、时长和来源；云端清单资料优先于远端不完整标签。
- 曲库支持“歌曲 / 专辑 / 歌手”浏览。专辑按专辑歌手与专辑名分组，内部按碟号/音轨排序。
- 读取资料建立缓存，按文件大小、修改时间和资料版本更新；后台补充，界面不等待全库扫描完成。

### 4.2 封面

- 本地优先级：用户指定封面 → MP3 内嵌封面（优先 front cover）→ 同目录 `cover.jpg` / `folder.jpg` 及 PNG 对应名称 → 默认磁带插画。
- 云端优先级：清单封面 URL/用户补充 → 可合理读取的内嵌封面 → 默认图。
- JPEG/PNG 缩略图缓存；大图片缩小后显示。对图片尺寸、标签字节数和缓存设置上限，防止一张封面耗尽内存。
- 损坏或不支持的封面仅影响图片显示，不中断歌曲播放。缺失封面显示可补充状态。

### 4.3 歌词

- 来源优先级：用户指定/同名 `.lrc` → 内嵌同步歌词 → 内嵌纯文本歌词；云端可通过清单指定歌词 URL。
- LRC 支持时间戳、多时间戳、全局 offset、常见头信息、空行和 UTF-8 BOM；中文历史编码须有兼容策略与测试。
- 有时间信息时逐行同步、高亮、自动滚动；没有时间戳时展示可滚动全文，不伪造同步。
- 支持调整歌词提前/延后，并按歌曲记忆；跳转、暂停、恢复、切歌后重新定位当前行。
- 歌词以实际已播放音频位置为准，不以下载进度或解码预读位置推进。
- 没有歌词时明确显示“暂无歌词”，网页可以上传/关联用户提供的 LRC。云端源未提供歌词时不承诺自动变出整首歌词。

歌曲资料、内嵌图片与同步/非同步歌词有对应的 ID3 标签能力；具体解析按版本校验，不能按固定偏移猜测。[ID3v2.3 规范](https://id3.org/id3v2.3.0)

### 4.4 中文文件名修复

这项同时涉及 Switch Link 配套 FTP 实现与电脑端，不限于播放器显示。

1. 记录最小复现：ASCII 临时文件可创建并回读，而相同目录的 UTF-8 中文 STOR/RNTO 失败。
2. 在可回退测试版中逐层验证 Windows 文件路径、FTP 命令原始 UTF-8 字节、命令解析、VFS 翻译和最终文件系统路径；保留真实 FS Result，不能仅看到 ENOENT 就猜根因。
3. 修复被证实出错的一层，加入路径字节/长度、UTF-8 边界及端到端回归测试。
4. 真机验收“中文目录 / 中文歌名 / 简繁混合 / 空格 / 括号 / 重命名 / 覆盖备份 / 下载回电脑”全流程；文件内容 SHA256 必须一致。
5. 不能再把拼音改名当作中文修复。资料标签恢复中文展示是另一项功能，也不能替代 FTP 修复。
6. 修复验证后，把本次部署的 5 首歌恢复为对应中文文件名，保留备份并避免重复曲目；不擅自改电脑音乐原件。

配套 Switch Link 修复独立版本化、备份并验证，不应破坏现有 HTTP 游戏安装功能，也不在正在安装时替换程序或重启服务。

### 4.5 SD 卡与云端双音乐库

- 曲库顶层有清楚的“SD 卡 / 云端”切换，条目带来源标识。
- SD：扫描默认 `/music`，支持配置其他显式目录；不扫描整张卡或不相关目录。
- 云端：保存多个有名称的 HTTP/HTTPS 源，支持 JSON 曲库、M3U/M3U8 歌单及单首 MP3 直链加入队列。
- 首次添加后记住 URL，支持编辑、删除、手动刷新和连接状态；不要求每次打开重新输入地址。
- 曲库刷新失败时保留上一份可用清单并标记过期，不清空用户收藏/队列。
- 支持歌单相对路径、空格、中文 URL、百分号转义及 BOM；明确拒绝错误格式，避免重复转义。
- SD 与云端进入同一播放队列，切库不停止正在播放的歌曲；未明确为同一歌曲的条目不靠相似歌名擅自合并。

推荐的自建曲库示例（字段约定为本项目设计，并非外部已有标准）：

```json
{
  "version": 1,
  "name": "我的音乐库",
  "tracks": [{
    "id": "track-001",
    "title": "示例歌曲",
    "artist": "示例歌手",
    "album": "示例专辑",
    "duration": 240,
    "audio": "audio/track-001.mp3",
    "cover": "covers/album-001.jpg",
    "lyrics": "lyrics/track-001.lrc"
  }]
}
```

### 4.6 在线播放

- 边接收边播放，不以下载完整歌曲作为正常开始播放的前提；保留手柄/触摸暂停、切歌和音量。
- 实际音频进度、网络缓冲进度分开。缺数据进入“缓冲中”，不能当作播完、自动切下一首或跳歌词。
- 歌单/VBR 标签没有提供总时长时仍可顺序播放，显示已播时间和“时长待获取”；不得沿用 0.2.0 对 samples==0 的拒绝条件。没有可靠时间—字节映射时不伪造整曲跳转，建立索引/缓存后再更新可跳转范围。
- 服务端支持有效 Range 响应时按需读取、跳转和重连；不支持时保持顺序播放，允许跳到已缓存范围，完整缓存后再开放其余跳转，并明确显示限制。
- 不假定 `Accept-Ranges` 或一次 HEAD 就能证明能力，验证实际 206/Content-Range、总长度与读取偏移；200/416/文件更新都有对应处理。
- 限量缓存；可查看占用、清理和调整上限。当前正在使用的片段不能被清理，空间不足时本地播放仍然可用。
- 网络请求有超时、取消、有限重试；切歌不等待长超时，旧请求/旧封面/旧歌词不能覆盖当前歌曲。
- 处理 401/403、404、失效链接、断网和重新连接；显示真实原因与重试入口，不无限转圈。
- HTTPS 校验证书与主机名；自建私有 CA 使用明确的信任配置，不能默认关闭证书验证。

HTTP 分段读取是可选服务端能力，服务器可能忽略 Range，因此客户端必须准备实际探测与降级路径。[HTTP 标准](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)、[libcurl Range](https://curl.se/libcurl/c/CURLOPT_RANGE.html)。HTTPS 信任采用 libcurl 的证书与主机校验机制。[libcurl 证书校验](https://curl.se/libcurl/c/CURLOPT_SSL_VERIFYPEER.html)

## 5. 界面安排

保留现有配色、字体气质、应用图标和磁带记忆点，避免把所有新功能挤进 0.2.0 的一个页面。

- 曲库：顶层 SD/云端来源切换，下方歌曲/专辑/歌手分类；有封面缩略图、搜索与收藏入口。
- 播放页：封面、中文歌名、歌手、专辑、进度和播放控制；可切换到磁带视觉。
- 歌词视图：当前歌词突出显示，支持全屏阅读、手动滚动、偏移调整和返回播放页；可用空间足够时显示封面与歌词双栏。
- 队列：显示即将播放的曲目及来源，允许移除和调整顺序。
- 设置：云端源、歌词偏移、缓存与曲库扫描。空内容、错误、断网、缓冲均有对应界面。

视觉布局先以可看的稿件确认，再接产品界面；本设计稿不把尚未展示的视觉细节当作用户已批准。

## 6. 建议一并纳入的补充项

以下为实现者建议，不冒充用户已点名要求。建议纳入 0.3.0 完整范围，用户可调整：

1. **搜索与筛选**：歌名、歌手、专辑；中文、英文和拼音首字母可搜索，资料更新后刷新索引。
2. **收藏与自建歌单**：可混合 SD/云端歌曲；保存/导入导出 M3U8 时标明本地路径的适用设备。
3. **断点续播**：保存歌曲、来源、位置、模式、音量；重开提供“继续上次”，源失效时保留记录并说明原因，不无限重试。
4. **网页配置信息**：在电脑网页添加云端源、选择音乐目录、上传/关联封面和 LRC；一次配置传入主机，减少在 Switch 上输入长 URL。

网页继续分清文件管理、游戏安装和音乐库入口。发布音乐时只暴露用户显式选择的目录；扩展现有 HTTP 服务采用独立音乐路由，不把游戏安装包列表当作音乐曲库。

网页配置的首版传入流程明确复用 Switch Link：主机处于其接收页时，电脑网页把已保存的源配置、资料关联信息通过 FTP 写入 `/config/papa-walkman/`，保留原文件备份并校验；返回随身听后读取。随身听保留系统键盘添加/编辑源的入口。首版不假定两个 NRO 能同时运行，也不要求随身听新增一个常驻 FTP 服务器。

**可再往后扩展**：云端歌曲主动下载到 SD、定时停止播放、FLAC/WAV/OGG、歌词翻译/逐字效果、均衡器。它们不是封面/专辑/歌词/中文修复/双源在线播放的替代项。

## 7. 架构与实现约束

- 扩展歌曲模型：稳定 ID、source、音频地址、标题、歌手、专辑、音轨、时长、封面/歌词引用、资料来源和缓存版本。
- 元数据层负责 ID3 与外部/云端资料合并；图片与歌词解析各自独立，不把网络/解析工作放进绘制循环。
- 来源接口接本地文件与 HTTP；继续保留音频解码/音频缓冲单一所有者，主线程读取快照。
- 网络生产者与解码消费端区分“临时无数据 / 真 EOF / 取消 / 出错”；不能以 0 字节网络读取混淆四种状态。
- 当前 MP3 打开过程会为精确时长建立索引，不能直接移到 HTTP 并照搬“全流扫描”；在线启动使用可用 VBR/清单信息和按需索引策略，不能先拉完整首歌。[minimp3 扩展接口](https://github.com/lieff/minimp3/blob/master/minimp3_ex.h)
- 封面、歌词与网络请求绑定歌曲 ID 和请求代次，避免快切歌后串图/串词。
- 收藏、源配置、索引与设置采用版本化存储和可恢复替换；保留 0.2.0 的音量/模式。
- 带口令/token 的源在日志和公共状态中脱敏；不进入 Git 或发布包。跨源重定向不携带其他来源的认证信息。
- 主格式 MP3；在线 HLS、WebDAV 和第三方音乐平台 API 不混入本轮明确选定的 HTTP/M3U 范围。
- 常驻内存目标不超过 96MiB，包括网络缓冲和封面；缓冲/缩略图具体尺寸由实现者以测试调整。磁盘缓存建议默认 512MiB，可设置。
- 本轮按前台 NRO 使用验收；不把游戏中后台常驻作为已承诺能力。HOME/返回、暂停和退出必须实测，不应崩溃或丢配置。

## 8. 开发顺序（同一版本内全部完成）

| 阶段 | 交付与验收 |

| 1. 中文与资料基础 | 定位并修复中文 FTP 路径；ID3v1/v2 资料模型、索引和旧配置兼容；中文目录/文件回读内容一致。 |
| 2. 专辑、封面、歌词 | 专辑组织、封面解码与缓存、同步/纯文本歌词；本地歌曲端到端展示，缺失资料可补充。 |
| 3. 云端曲库与播放 | JSON/M3U 接入、网络数据源、边下边播、缓冲、跳转、断网与限量缓存；本地/云端队列互通。 |
| 4. 界面与便利功能 | 源切换、专辑/播放/歌词/队列界面，以及建议的搜索、收藏、续播和网页配置。 |
| 5. 联调与真机验收 | 验证全部明确要求和已选补充项；回归原播放、FTP 文件管理和 HTTP 游戏安装；打包与回退。 |

不能只完成本地封面歌词就把云端移到另一个未定版本；也不能先做联网列表而没有真正在线播放。

## 9. 验收矩阵

- 本地：带/不带标签的 MP3；ID3v1、v2.3、v2.4；UTF-8/UTF-16 与历史中文；不同采样率、单/双声道、坏标签和坏音频。
- 封面：内嵌 JPEG/PNG、文件夹封面、远端封面、缺失/损坏/超大图片、快切歌后的请求串图。
- 歌词：LRC 多时间戳、offset、无序/重复时间戳、纯文本内嵌歌词、无歌词；暂停/快进/切歌/在线缓冲后仍同步。
- 云端：JSON、普通/扩展 M3U、UTF-8 M3U8、相对/绝对/中文 URL、曲库刷新失败、同名不同源、401/404、链接更新。
- 流式：支持/忽略 Range 的服务器、200/206/416、无 Content-Length、截断、重连、缓存满、读缓存时切歌与退出；真正边下边播。
- 中文传输：中文目录和文件的创建、上传、改名、覆盖备份、列出和下载，SHA256 回读一致；修复后恢复本次五首歌的中文名。
- 不回归：0.2.0 的队列/随机、暂停缓冲所有权、重采样连续性、EOF 事件、触摸和配置恢复；保留配套 Switch Link 的游戏安装功能。
- 真机：至少 30 首本地/云端混合播放、50 次连续切歌、断网恢复；稳定前台播放至少 2 小时。歌词同步偏差目标在受控样本中不超过 250ms，界面操作应在 200ms 内有反馈。
- 在线首播目标：受控局域网可用吞吐不少于 1MiB/s、无额外服务器延迟且资料体积受控时，5 秒内开始出声；同时记录实际请求量，证明没有先下载完整首歌。
