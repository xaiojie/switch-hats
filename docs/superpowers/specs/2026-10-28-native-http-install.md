# Switch Link native HTTP installation correction

User correction: installation must occur inside our own Switch Link console application, NOT in DBI. The webpage initiates an installation after choosing a package; payload transfer uses HTTP. FTP stays for SD file operations. Do not start or resume a real installation without a fresh user request; previously stopped test remains stopped. Existing HTTP/files and SD contents must survive development.

Chosen implementation reuses Sphaira's existing random-access yati::source::Http and installation engine, replacing the slow FTP stream for game payloads. PC sends a bounded, idempotent UDP install command to the discovered native client; console pulls the package over HTTP and POSTs a per-job capability-authenticated result. UI/console progress uses genuine native step counters. No IP typing, external DBI dependency, or fake success. Console update requires new NRO0.2.1 in an independent directory; old0.1.1 remains a fallback.

## Protocol contract (shared by native, Python and web)

Native beacon retains type=switch-link,version=1 and existing device identity/FTP/progress fields, adds app_version=0.2.1,http_install_supported=true,http_install_ready=bool,command_port=28772,http_formats=["nsp","xci"]. Only advertise compressed formats if the build actually enables them.

Install UDP on28772, UTF-8 JSON <=4096 bytes:
`{type:"switch-link-install",version:1,device_id:<32hex>,id:<32hex>,name:<original name>,wire_name:<id>_<name>,url:"http://<PC sender IPv4>:8080/link-files/<id>/<64hex token>/<percent-encoded name>",result_url:"http://<same host:port>/link-result/<id>/<same token>",size:<positive uint64 <=128GiB>}`.
Reject mismatch device, bad IDs, controls/traversal, overlong names (UTF-8<=200 bytes), non-HTTP/foreign URL origin, mismatched job/token in URL/result, unsupported extensions. New command only at receiver page and idle. Persist the last accepted job ID before installation to reject retransmissions/replays even after restarting app; duplicates must not launch a second install. UI thread stays nonblocking; use bounded receive parsing.

On receiver Menu::Update, consume a validated pending command and push existing ProgressBox. Worker calls BeginInstallReceipt(wire_name), constructs yati::source::Http(url,"","",pbox->GetToken()), yati::InstallFromSource(...,wire_name,config sd=true,source_size=size), then WriteInstallReceipt and sends JSON POST to result_url. Result: `{id,device_id,filename:<wire_name>,success:bool,result:<u32>,registered_titles:<uint>,message:string}`. Success requires Result0 AND registered_titles>0. Token is only in capability URLs; never publish it in ordinary status. POST bounded/retried briefly, native terminal beacon continues. Optional persistence of receipt is kept.

PC public HttpShare serves link-files only for valid job/token/name/device peer; it also accepts bounded POST link-result with matching peer and payload. Never let ordinary HTTP completion mark installed. Existing /files library remains available. Local API POST `/api/http-install` JSON `{name,expected_device}` queues an existing local library file after verifying selected live native http_install_supported; GET status/jobs includes resulting jobs alongside FTP jobs. queued cancel allowed, active HTTP install cannot be silently cancelled. File operations/device switches blocked while installing. Startup never replays jobs.

Job fields: id,name,kind=install,transport=http,receiver_mode=switch-link-http,state,stage,bytes_done,bytes_total,speed,progress,error,created_at,updated_at; native_progress/native_bytes_done/native_bytes_total/native_speed/native_stage from verified native beacon; network_bytes actual HTTP bytes sent (may include random-access rereads). UI may show current native step percentage, but must label it as such. Final registration is indeterminate until result confirms success. No inference of install success from native percentage or HTTP bytes.

Web library remains source preparation, with install buttons per package and main “选择安装包并安装”. Capture device ID at file chooser opening; FTP/device changes cannot redirect pending install. Upload package first if new, then submit HTTP installation only to the captured device. If target changed or incompatible client is open, retain file but do not install. Existing packages can be installed without reuploading. Show own-client instructions, not DBI/SwitchLibrary. Native0.1.1 or DBI must prompt upgrade and never fall back to FTP installation.
