## Shared contracts

`core.hpp` retains first three aggregate fields `Track {path,title,artist}` and adds defaulted:
`id, album, albumArtist, cover, lyrics, sourceId` strings; `trackNumber, discNumber` ints; `duration` double; `SourceKind source` (`SD`, `Cloud`). `cover` and `lyrics` are local paths or absolute URLs. IDs are namespaced per source; SD fingerprints may be cached, and saved source ID + catalog ID identifies cloud songs.

`sources.json`: `{"version":1,"sources":[{"id":"...","name":"...","url":"http...","enabled":true}]}`.

`overrides.json`: `{"version":1,"tracks":{"<track-id>":{"title":"...","artist":"...","album":"...","cover":"...","lyrics":"..."}}}`.

Cloud JSON is exactly the example in the spec: `version,name,tracks[{id,title,artist,album,duration,audio,cover,lyrics}]`. Relative references resolve against the final catalog URL. M3U `#EXTINF` data is used if present; absent duration remains unknown, not zero-length EOF.

## Review Focus

- Unknown durations, lack of Range, slow/incomplete data and cancel during blocked reads must not cause fake EOF or lock the UI.
- ID3v1 GBK and ID3v2 UTF-16, corrupt lengths, embedded artwork and SYLT units must produce bounded, valid results.
- Metadata/art/lyrics work must not retain multi-MiB images for all 10000 songs or overwrite newer selection.
- Native UTF-8 path failure must be traced to the failing layer and verified on real SD without damaging original names/content.
- Web directory selection, path traversal, stale device binding and active installs must preserve existing safety and never expose unrelated files.
