# 爬爬的随身听 · 功能设计 v0.1

> Switch 上的本地音乐播放器。外观是一台会转的磁带机，插卡即听，不联网。

- 代号：`papa-walkman`
- NRO：`papa-walkman.nro`
- 目标路径：`sdmc:/switch/papa-walkman/papa-walkman.nro`
- 配置：`sdmc:/config/papa-walkman/`
- 音乐：默认 `sdmc:/music`

---

## 0. 先说三条硬约束（决定整个产品的形状）

### ① 不能后台播放

Homebrew 进程按下 Home 就会被挂起或干掉，没有例外。所以「一边打游戏一边听」在普通 NRO 里做不到——那是 **sysmodule**（sys-tune 那条路），要常驻系统、崩溃会连累整个系统，不进第一版。

**这意味着：爬爬的随身听是「专门拿来听歌」的机器。** 想听就打开它，听完再退出。这个限制必须先接受，否则做出来会失望。

### ② 没有蓝牙耳机

Switch 的蓝牙音频只在系统游戏模式里生效，homebrew 拿不到。**只能用 3.5 mm 耳机孔或 HDMI 出声。**

### ③ 启动方式影响稳定性

| 方式 | 内存 | 稳定性 | 说明 |
|---|---|---|---|
| hbmenu（相册进入） | ~380 MB | 一般 | 系统开别的 applet 会被挂起 |
| title takeover（借一个游戏进入） | ~3.9 GB | 好 | 会关掉那个游戏，推荐 |

第一版两种都能跑，但会在设置页提示「用 title takeover 更稳」。

## 1. 格式支持

| 格式 | 版本 | 解码器 | 说明 |
|---|---|---|---|
| MP3 | MVP | mpg123 | 最常见，必须稳 |
| FLAC | MVP | dr_flac（单头文件） | 无损，首选高音质 |
| WAV (PCM) | MVP | 自写 | 简单，兜底 |
| OGG Vorbis | MVP | stb_vorbis | 单头文件，省依赖 |
| Opus | P1 | libopusfile | 体积小，但库大 |
| AAC / M4A | 不做 | — | FAAD/FFmpeg 太大，收益低 |
| APE / TAK / WMA / DSF | 不做 | — | 冷门 |

**输出统一 48 kHz / 16 bit / 立体声**（Switch audren 的原生格式，重采样一次到位，避免每首歌切格式爆音）。输入 44.1 / 48 / 88.2 / 96 kHz 都接受。

**无缝切歌（gapless）**：FLAC / Vorbis 天然连续；MP3 按帧边界切，跳过 LAME 头，能做到无损拼接。切歌加 20 ms 交叉淡入淡出，防「啪」声。

## 2. 界面：一台磁带随身听

主视觉是**米色机身 + 双转轮 + 橙色按键**，转轮按播放进度旋转，暂停时停住。这是整个产品的记忆点，不是皮肤，是核心。

三页，左右切换：

```
│  │  ┌──────────────────┐  │  │
│  │  │   晴天            │  │  │   ← 大字歌名

```

### 02 / 曲库（列表页）

- 三个入口：**目录**（按 SD 卡文件夹树）/ **全部歌曲** / **播放列表**
- 列表项：序号 · 标题 · 歌手 · 时长
- 顶部搜索框（P1：支持拼音首字母，输入 `qt` 命中「晴天」）
- 角标：当前播放曲目用橙色高亮 + 小喇叭图标

### 03 / 设置

- 扫描目录（可加多个，默认 `/music`）
- 息屏播放（关背光但继续出声）
- 音量上限保护
- 字体大小 / 主题（米色 / 银灰 / 深色）
- 关于（版本、SD 卡剩余空间、歌曲总数）

### 按键

| 按键 | 功能 |
|---|---|
| A | 播放 / 暂停 |
| B | 返回上一级 |
| X | 加入队列（在列表里） |
| Y | 随机开关 |
| L / R | 上一个 / 下一个文件夹 |
| ← / → | 上一首 / 下一首 |
| ↑ / ↓ | 音量 ±5 |
| ZL / ZR | 快退 / 快进 10 秒 |
| 触摸 | 点条目播放、拖进度条、滑页 |

## 3. 曲库与索引

**增量索引**，不能每次启动全盘扫。

- 缓存文件：`/config/papa-walkman/library.json`
- 每条记录：`path / size / mtime / title / artist / album / track / duration / format`
- 启动流程：读缓存 → 只对 **mtime 或 size 变化**的目录重新扫 → 后台补新文件
- 扫描分片：每帧最多处理 8 个目录项，界面不卡；显示「正在索引 1234/5000」
- 大卡估算：1 万首首次约 40–60 秒，之后每次 < 3 秒

**元数据**

| 来源 | 字段 |
|---|---|
| ID3v2 (MP3) | 标题 / 歌手 / 专辑 / 音轨号 / 封面 |
| VorbisComment (FLAC/OGG) | 同上 |
| WAV INFO | 部分字段 |

封面用 `stb_image` 解码（JPEG/PNG），缩到 256×256 缓存。

**中文显示（关键难点）**

NRO 里塞完整 CJK 字体会让包变成几十 MB。方案：

1. 内置只放 ASCII + 少量符号（~200 KB）
2. CJK 字体从 SD 读：`/switch/papa-walkman/font.ttf`（推荐思源黑体 / Noto Sans SC 子集）
3. 找不到就退回 ASCII，界面提示「把 font.ttf 放进 /switch/papa-walkman/」

## 4. 播放行为

- **队列**：顺序 / 单曲循环 / 列表循环 / 随机（真随机，一轮内不重复）
- **队列编辑**：加入队列、下一首播放、清空、拖动排序
- **断点续播**：退出时记 `song + 秒数`，下次启动问「继续上次？」
- **音量**：0–100 映射到 dB 曲线，记忆到配置文件
- **防爆音**：切歌/暂停/恢复都做 20 ms 淡入淡出
- **坏文件**：解码失败 3 秒超时 → 跳过并 toast「这首歌读不了」，不卡死队列

---

## 5. 播放列表

- 读写 `.m3u` / `.m3u8`（相对路径，UTF-8）
- 存放 `/config/papa-walkman/*.m3u`
- PC 上整理好的歌单拷进 SD 就能直接读

---

## 6. 省电与屏幕

- 播放中允许关背光继续出声（设置项「息屏播放」，按任意键亮屏）
- 阻止系统自动休眠（`appletSetAutoSleepDisabled(true)`）
- 不做 CPU 超频；解码一个 MP3 只用 1 个核，其余空闲

**目标**：连续播放 ≥ 5 小时（Switch 标称 4.5–9 h，纯播放应有 6 h 以上）。

---

## 7. 传歌怎么传

不重复造轮子，复用已有的 Switch Link：

1. 打开 Switch Link 的网页（`127.0.0.1:8088`）
2. 用「SD 文件」把歌上传到 `sdmc:/music`
3. 回到随身听，自动增量索引

也在随身听设置页显示一句提示：「歌放 /music，用 Switch Link 传」。

## 9. MVP 边界（第一版做什么）

**必须有**
- MP3 / FLAC / WAV / Vorbis 播放
- 目录浏览 + 全部歌曲列表
- 队列、上一首/下一首、循环/随机
- 进度条拖动、音量、暂停/继续
- 磁带动画 + 中文歌名
- 增量索引缓存、断点续播

**可以没有**
- 封面显示、m3u 导入、拼音搜索、息屏播放、增益归一化、主题切换、Opus

**明确不做**
- 后台播放（需要 sysmodule）
- 蓝牙耳机
- 流媒体 / 在线曲库
- AAC/M4A

## 10. 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 框架 | libnx + SDL2 | `switch-sdl2` 的音频后端直接走 audren，省掉自己写缓冲队列 |
| 解码 | mpg123 / dr_flac / stb_vorbis | 前两个成熟，后两个单头文件零依赖 |
| 重采样 | libsamplerate 或自写线性 | 44.1→48 用线性够用，追求音质上 libsamplerate |
| UI | SDL2 渲染 + 自研立即模式控件 | 不引 raylib，避免额外依赖；磁带绘制用 SDL 图元 + 少量 PNG |
| 字体 | stb_truetype | ASCII 内置，CJK 从 SD 加载 |
| 图片 | stb_image | 封面 |
| 配置 | 手写 JSON（yyjson，Sphaira 已在用） | 体积小、快 |

## 11. 构建环境现状（需要先解决）

本机 `/opt/devkitpro` 目前是个**空壳，只有 `pacman` 目录**，没有 `devkitA64`、`libnx`、`portlibs/switch`。之前 Switch Link 的 NRO 是用便携工具链（`build.ps1` + 工作目录里的 devkitA64）或离线脚本产出的。

1. **官方安装器**：装 devkitPro 的 macOS 包，`dkp-pacman -S switch-dev switch-sdl2 switch-mpg123 switch-libvorbis`

## 12. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| applet 模式下音频初始化失败 | 相册进入没声音 | 实测；失败则强制提示用 title takeover |
| CJK 字体体积 | NRO 太大 | 字体放 SD，不内置 |
| 切歌爆音 | 听感差 | 20 ms 淡入淡出 + 预填充静音 |
| 坏文件卡死解码线程 | 整机假死 | 独立解码线程 + 3 秒看门狗 |
| 大卡扫描慢 | 启动体验差 | 增量索引 + 分片扫描 |
| Switch 休眠时音频中断 | 歌停 | 播放中禁用休眠 |

## 14. 已拍板的决策（2026-10-29）

1. **外观**：复古磁带随身听。米色机身 + 双转轮 + 橙色按键，转轮随进度旋转。不做极简版、不做主题切换。
2. **格式**：只要 MP3 / FLAC / WAV / OGG Vorbis。**不做 M4A/AAC**，包体保持小。
3. **启动方式**：接受「必须借一个游戏进入」（title takeover），稳字优先。相册直进作为兼容路径保留，但设置页会提示不稳定。
4. **歌单**：第一版就支持 `.m3u` / `.m3u8` 读写，用来搬 PC 上整理好的歌单。

由此产生的工作量：

- 需要手绘磁带机身、两个转轮、按键三组矢量素材（SDL 图元 + PNG）
- 不需要 AAC 解码器与相应依赖
- 需要在文档/SD 卡说明里写清楚「怎么用 title takeover 启动」
- 需要额外一个 m3u 解析器（相对路径、UTF-8 BOM、`#EXTM3U` / `#EXTINF` 兼容）
